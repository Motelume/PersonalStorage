# 稳定架构与跨电脑复用

程序版本0.4.1，通用规则包`personalstorage.education` 1.2.0，现有资料配置schema仍为3.0。本机状态与凭据不跟随Git或程序包分发。

## 四个边界

| 层 | 内容 | 保存与复用方式 |
|---|---|---|
| 程序 | Python、网页、桌面窗口、测试、构建脚本 | Git同步或复制完整桌面程序目录 |
| 通用规则 | 固定顶层、12个固定子目录、分类边界和判断顺序 | 随公开模板发布，按版本受控更新 |
| 私人资料库 | 原资料、具体课程项目、个人规则、任务和执行条件 | 每台电脑独立保存，更新通用包不覆盖 |
| 本机状态 | 默认根路径、SQLite索引、审核记录、DPAPI密钥、缓存 | 默认放本机用户状态目录，不进入程序包和Git |

程序目录与资料目录不能相同或互相包含。课程、项目、比赛、学科及事项按需创建；不为复用而硬编码私人名称，不根据年份批量预建任务目录。

## 新电脑首次使用

1. 复制完整的桌面程序目录，运行`PersonalStorage.exe`。打包版自带Python，电脑需要WebView2 Runtime。
2. 默认资料位置不可用时，应用弹出本机目录选择器。可选已有配置的资料库，也可经明确确认在所选目录初始化空架构。已有文件不会被搬动或覆盖。
3. 已保存的本机默认路径放在`machine.sqlite3`中，与程序安装位置无关。换一个程序目录或更新应用版本，不会丢失这个选择。
4. 在AI管理重新输入自己的DeepSeek密钥。DPAPI密文不能作为跨电脑密钥交换格式。
5. 按该电脑的实际课程、项目、比赛和事项维护任务绑定。不要复制另一台电脑的索引数据库来接管资料。

桌面原生“设置”菜单可选择下次启动使用的目录；也可使用`--choose-root`强制重新选择。当前窗口继续使用原资料库，避免运行中切换数据库身份。

源码/命令行用户：

```powershell
.\run.cmd --root "E:\PersonalStorage" setup
.\run.cmd configure-root "E:\PersonalStorage"
.\启动界面.cmd
```

已有配置的目录跳过setup。路径优先级：`--root` > `PERSONALSTORAGE_ROOT` > 程序旁`.local/config.json` > 本机已保存选择 > `D:\PersonalStorage`。显式覆盖仍优先于菜单里保存的默认选择。

## 私人规则与通用规则

```text
资料根目录/
  AGENTS.md
  _整理规则/
    分类配置.json          程序实际读取的唯一有效配置
    通用分类规则.md        公开规则包维护的说明
    通用规则版本.json      包版本、源指纹和字段基线
    整理规则.md            本机私人偏好和例外
    执行记录/              运行时生成，不随程序分发
  00_收件箱/ ... 99_临时待整理/
```

源模板不含机器路径、个人任务或实际文件清单。初始化时把通用说明与本机私人入口分开；旧资料库保留原有完整私人规则，不强制重写文件。

运行时仍只读取`分类配置.json`，不引入多套隐式配置合并来源。通用说明和私人约定由AI/人工一起理解；可执行条件仍须明确发布，不能由自然语言直接触发移动。

## 通用规则升级

```powershell
.\run.cmd rules-status
.\run.cmd rules-update
.\run.cmd rules-update --approve
```

前两条只读预览。批准后先备份管理数据库和原配置，再补充缺失的通用字段；只有能证明仍与上一通用基线一致的字段才跟随新版更新。已修改字段保留，`tasks`、`executable_rules`、类别、保护约束、明确私人偏好及原个人说明不被覆盖。自行修改过的通用说明也保留并提示人工比较。

schema不兼容、存在未完成操作或规则在预览后变化时拒绝更新。规则内容变化后旧计划作废，持续后台授权撤销；不自动搬动资料或创建新的私人任务。规则包版本与本机个人策略版本分别记录。

## 本机状态与备份

默认用户状态目录是`%LOCALAPPDATA%/PersonalStorage`：`machine.sqlite3`保存默认路径，`credentials.sqlite3`保存DPAPI密文，根路径派生的子目录保存该资料库的索引、审核和备份。高级隔离测试可用`PERSONALSTORAGE_HOME`选择独立状态目录；它不是资料同步路径。

根路径中的点段会规范化；Windows大小写变化不会另建逻辑身份。卷身份和schema仍校验。真正改名、换盘或整体迁移资料时，仍需停止服务并明确迁移状态，不能仅复制数据库或修改盘符冒认原卷。

## 升级程序

先关闭旧应用和网页服务，再拉取代码或运行新版本程序。程序和机器配置分离，因此不需要把路径或密钥写进源码。通用规则使用上述单独预览更新流程，资料和私人约定保持原样。原资料备份、管理快照与代码备份分别维护。
