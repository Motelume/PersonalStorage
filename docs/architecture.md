# 架构与维护

浏览器 → `web.py`本机服务 → `Application` → 计划、安全执行器与SQLite。CLI共用同一Application入口。

| 模块 | 职责 |
|---|---|
| paths / config / setup | 规范路径、本机持久默认设置、通用模板初始化 |
| rule_package | 通用包版本基线、预览、备份和保留私人修改的更新 |
| discovery / extraction | 收件箱发现、稳定性检查、只读文字提取 |
| scanning | 仅生成建议的元数据扫描、批次稳定窗口与有界提取缓存；不生成可执行计划 |
| activity | 七天的任务历史；与长期保存的移动审计分离 |
| inboxes / importing / transfer | 外部来源与方式、身份边界、校验导入、持有目标句柄时按版本清理原件、导入标记 |
| classification / ai_audit | 规则后AI分类、补充说明、按钮触发的全库复核与持久内容缓存 |
| policy / planner | 白名单规则、任务上下文、单次人工决定与预览 |
| executor / recovery | 同卷不覆盖移动、前后校验、中断恢复与受限撤销 |
| state / maintenance | 身份隔离、索引与版本、观测和内容变化 |
| review / reports | 离线审核、手动完成待办、历史与状态 |
| snapshot | 一致性管理数据库快照和规则文本说明 |
| web / web_static | 回环接口、归档工作队列与七页前端；页面状态独立、后台任务结果通知 |
| ai / model_client / credentials | 明确授权的DeepSeek审核、用量管理、DPAPI凭据；与移动执行器分离 |
| desktop | 内嵌WebView2窗口，共用网页与本机HTTP适配 |

每个工作线程创建自己的SQLite连接。长任务进入单工作队列；所有实际移动仍受进程间锁约束。HTTP对象句柄和预览属于当前服务会话，重启后重新读取列表及生成预览。

前端异步动作捕获来源页面和对象，不在结果返回后读取当前页面的全局选中项。切页不停止轮询、不自动跳回；预览结果在来源页面待阅。`ui_tasks`只记录动作类型、时间、状态和受控摘要，不存请求体、密钥、提示词或正文。任务活动按七天清理；`operations`及恢复事件继续保留。

建议扫描不计算内容哈希、不持久化整份移动计划。源元数据变化会使缓存和建议失效；执行预览重新解析和完整哈希、检查归属及同名冲突，执行前后继续完整核验。元数据缓存从不用于替代执行完整性校验。

外部来源使用`@inbox/<来源ID>/<相对位置>`作为逻辑标识，由登记的绝对目录与卷/目录身份解析，不能借此扩大核心`safe_path`范围。预览与执行可合并库内移动和外部导入，但分开调用执行器。每来源`import_mode`为`copy`或`move`，缺省`copy`；`mode_revision`使切换前的计划失效，即使又切回原方式也须重新预览。外部计划类型`external_import`，动作分别为`external_copy`或`external_move`。资料先复制到库内管理暂存，逐文件刷盘并完整校验，再以不覆盖的同卷重命名发布目标。

`constraints.no_delete`与`same_volume_only`仍约束核心库内执行器，外部来源转移是用户明确选择并逐次确认的独立导入流程；模型不能扩大这个范围。

转移在`verified`事件持久写入后清理原件。目标文件保持只读共享句柄直至整包清理结束，拒绝并发写入、重命名和删除；原目录及祖先持有禁止重命名的目录句柄，源文件取得独占、拒绝重解析点的句柄后再次核对SHA-256、大小、mtime与身份，再用`FileDispositionInfo`标记该句柄删除。不调用源目录的递归删除，只对清单中的文件和空目录操作。目标文件句柄以原生方式持有，哈希借用短生命周期CRT流，避免大包同时占满CRT文件描述符。

目标注册和`source_retained`状态在同一事务内落账；清理失败不阻塞后续归档。重试使用会话内15分钟票据，绑定剩余清单、源身份、来源方式版本和策略，重新验证副本，仅处理原清单中仍未变化的成员。未知新增内容拒绝清理。恢复只对账，不删除原件；外部操作不进入库内撤销执行器。Windows接口依据：[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info)。

全库复核使用独立进程间租约，单批AI审核仍取得原执行锁；停止请求绕过工作队列，在当前API批次结束后生效。`ai_location_cache`按内容哈希与相对位置、策略、模型、补充说明和归属状态失效，不靠文件时间判断内容不变。每日批数独立持久计数，不随最近200条调用历史的截断而重置。

## 配置与资料

运行时读取资料根目录下的`_整理规则/分类配置.json`。程序包内模板只用于新建空资料库，不自动覆盖已有规则。语义规则、任务和人工例外留在对应电脑本机；仓库中的示例不是个人分类配置。

模板公开固定架构、细分分类边界及判断顺序。`initialization.fixed_subdirectories`用于创建固定子目录；`subcategory_rules`和`classification_rules`供人工与AI读取。学期、课程、任务和主题按需创建，尖括号占位符不创建为实体目录。语义规则不是自动执行条件；自动执行仍使用`executable_rules`。

通用包、私人有效配置和本机状态的完整契约见[portability.md](portability.md)。保留单一有效分类配置，不通过隐藏的多层覆盖改变运行结果；更新模块只按已记录基线更新未被私人改动的通用字段。

状态目录按规范化根路径派生身份。资料根路径改名后，应在停止服务和其他CLI执行器的前提下备份并迁移状态身份，保留历史文件相对路径。旧预览必须失效；持续授权应撤销并在新身份下重新决定。历史操作仍按相对源/目标解释，不自动改写原资料正文。

## 测试

`unittest discover`使用临时目录，不在真实资料库移动文件。Web测试覆盖来源校验、已选独立计划、过期预览、待确认分流、撤销检查、授权和启动分离、外部已处理归档与历史保留。

`tools/frontend_smoke.cjs`启动临时资料服务，并通过本机Edge验收完整操作。临时资料由`tools/web_fixture.py`生成。测试退出后销毁临时目录。应用运行不依赖Node或Playwright。

## 只读目录总览

`overview.py`提供有界目录分页、元数据描述、名称搜索及本机布局/关联管理。`overview.js`和`overview.css`实现无第三方图形运行库的SVG连线、HTML卡片、双侧树布局、平移缩放、小地图、目录树与搜索定位；漂浮由同一动画循环同步更新节点和连线。不可见页面停止动画，减少动态效果设置优先。

浏览不复用归档目标选择器，避免将归档范围过滤误用于真实目录总览。只读目录请求不取得文件执行锁，名称搜索使用独立单线程池与取消事件，不进入AI/文件操作队列；元数据写入仅保存布局与手动关联。关联端点同时绑定相对路径和文件系统身份，失效不自动重绑。所有打开操作只打开文件夹，文件节点只打开父目录。分页和绘制有上限，搜索有结果与枚举上限，详情不读取正文。

## 离线OCR与提取缓存

`ocr.py`提供本机OCR设置、固定模型校验、页级原生文字优先、低分行过滤与私有内容缓存。`extraction.py`为图片/PDF计算内容键，缓存未命中时生成不可变临时副本，在有超时的独立进程内解析并在结束后核对原件。工作进程断开网络能力，不执行源文件；模型与字体均为显式本地路径。普通文本提取不引入全库内容哈希。

规则扫描和外部来源共享提取协议，内存建议缓存绑定OCR设置/代际；包内代表文档增加图片候选但优先文字文档。AI继续使用有限文字摘录，不接收整图或整PDF。缓存原始识别结果按内容、配置和协议复用，文件名在返回时绑定当前对象，避免改名后引用旧名称。缓存失败不阻止一次性识别，失败/超时不写成功缓存；SQLite连接异常时关闭句柄，清理代际阻止旧请求回填。
